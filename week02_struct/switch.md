switch - конструкция ветвления, выбрать один из нескольких блоков кода по значению выражения, по условию или по типу интерфейсного значения. выбрать один из нескольких вариантов выполнения кода в зависимости от значения, условия или типа.

switch в Go отличается от switch в Java/C/JavaScript - в Go не нужен обязательный break после каждого case, выход из ветки происходит автоматически.

Если условий много и они образуют понятный набор вариантов, switch читается лучше.

context switch - переключению контекста выполнения на уровне конкурентности, потоков или планировщика. тема ближе к рантайму, горутинам и конкурентности, а не к switch case как синтаксису языка.

```go
switch day {
    case "monday":
        fmt.Println("Начало недели")
    case "friday":
        fmt.Println("Почти выходные")
    case "saturday", "sunday":
        fmt.Println("Выходной")
    default:
        fmt.Println("Обычный день")
}
```

Switch подходит:
у вас много вариантов одного действия
есть несколько возможных значений одной переменной
нужно заменить длинную цепочку if else
нужно проверить набор условий без лишней вложенности
нужно определить тип значения в интерфейсе

Меньшу шума, легче читать.

- Go берёт значение переменной
- Последовательно сравнивает его с каждым case
- Находит первое совпадение
- Выполняет код внутри этого блока
- Выходит из switch


После switch может стоять не только переменная, но выражение, которое возвращает значение.

```go
a := 7
    switch a + 2 {
    case 9:
    fmt.Println("nine")
    case 10:
    fmt.Println("ten")
}
```

default почти всегда полезен, помогает:
- обработать неожиданные значения
- не оставлять «тихий» путь без результата
- сделать поведение кода очевиднее

```go
role := "guest"
switch role {
    case "admin":
    fmt.Println("Полный доступ")
    case "editor":
    fmt.Println("Можно редактировать")
    default:
    fmt.Println("Ограниченный доступ")
    }
```

Если убрать default, при новом неожиданном значении код ничего не сделает. Иногда нормально, часто плохая идея.

#### В Go не нужен обязательный break после каждого case
Во многих языках switch по умолчанию проваливается дальше, если не поставить break.
В Go наоборот: после первого совпавшего case выполнение останавливается автоматически.

```go
x := 2
switch x {
    case 1:
    fmt.Println("one")
    case 2:
    fmt.Println("two")
    case 3:
    fmt.Println("three")
}

two
```

Ни three, ни что-то ещё дальше не выполнится.
удобная особенность, убирает целый класс случайных багов.

break не нужен - код чище и проще.
автоматического проваливания в следующий case (fallthrough) нет.

switch в Go работает с выражениями, результатами функций, типами интерфейсных значений. сравнивать значения разных типов, если сравнение допустимо.

```go
os := "linux"
switch os {
    case "windows":
    fmt.Println("Windows")
    case "linux":
    fmt.Println("Linux")
    default:
    fmt.Println("Unknown OS")
}

switch time.Now().Weekday() {
    case time.Saturday, time.Sunday:
    fmt.Println("It's the weekend")
    default:
    fmt.Println("It's a weekday")
}
```


В Go можно писать switch без выражения. При сложных условиях, которые легче читать свреху вниз.

```go
x := 10
switch {
    case x < 5:
    fmt.Println("x меньше 5")
    case x < 15:
    fmt.Println("x меньше 15")
    default:
    fmt.Println("x больше или равно 15")
}
```

Go будет идти по case сверху вниз и искать первый, где условие истинно.

### В Go есть type switch
используется регулярно, особенно там, где есть interface.

Default, несколько значений в case и switch без выражения - набор возможностей, который делает go switch case действительно удобным, а не просто аналогом того, что я уже видел в другом языке.

Если для нескольких значений выполнить одинаковое действие, не копировать код в несколько case - перечислить через запятую.

```go
fruit := "apple"
switch fruit {
    case "apple", "pear":
    fmt.Println("Это фрукт")
    case "carrot":
    fmt.Println("Это овощ")
    default:
    fmt.Println("Неизвестный продукт")
}
```

Это и короче, и чище.
полезен, когда несколько равнозначных статусов, несколько допустимых ролей или несколько вариантов входных значений.
одинаковое действие не повторили в пяти ветках подряд.

Когда default особенно важен
default это не просто ветка на всякий случай - защита от молчаливых ошибок.

```go
status := 503
    switch status {
    case 200:
    fmt.Println("Успешно")
    case 400:
    fmt.Println("Неверный запрос")
    case 404:
    fmt.Println("Не найдено")
    default:
    fmt.Println("Неожиданный статус")
}
```

завтра новый статус или в код прилетит, чего не ожидали - default не даст программе выглядеть, будто всё нормально.
Не забывать про default там, где неожиданные значения реально возможны. опасно в коде, который работает с внешними данными: API, ввод пользователя, конфиги, статусы.

### Switch без выражения

```go
t := time.Now()
switch {
    case t.Hour() < 12:
    fmt.Println("До полудня")
    default:
    fmt.Println("После полудня")
}
```

Go проверять каждое условие в case как булево выражение. удобная форма для логики вида:
если условие 1
иначе если условие 2
иначе если условие 3
иначе по умолчанию

switch без выражения часто лучше if else if
структура визуально ровнее. Когда условий много, читать такой код проще.

Порядок case критичен.

```go
score := 82
switch {
    case score >= 60:
    fmt.Println("Нормально")
    case score >= 75:
    fmt.Println("Хорошо")
    case score >= 90:
    fmt.Println("Отлично")
}
```

для 82 сработает уже первый case, потому что 82 >= 60 это true. до более точных условий Go уже не дойдёт.

### Break и fallthrough в switch
Зачем нужен break, если Go и завершает case после выполнения. в простых примерах break не нужен.
полезен внутри case, если хотите выйти из switch раньше по условию.

```go
command := "cat"
args := []string{}
switch command {
    case "echo":
        fmt.Println("echo command")
    case "cat":
        if len(args) == 0 {
            fmt.Println("Usage: cat <filename>")
            break
        }
        fmt.Println("reading file")
    default:
        fmt.Println("unknown command")
}
```

break - внутри ветки дальше ничего не выполнять, выйти из switch сейчас.
break не как защита от проваливания в следующий case, а как способ досрочно закончить текущую ветку.

fallthrough - после выполнения текущего case перейти к следующему, даже если его условие не совпадает.

```go
x := 2
switch x {
    case 1:
        fmt.Println("x = 1")
    case 2:
        fmt.Println("x = 2")
    fallthrough // перейти дальше в case 3, не проверяя условие, равно ли x тройке
    case 3:
        fmt.Println("x = 3")
    case 4:
        fmt.Println("x = 4")
}

x = 2
x = 3
```

Fallthrough не проверяет условие следующего case, продолжает выполнение следующего блока.
легко делает код менее очевидным. Если switch читается как набор независимых веток, то fallthrough ломает это ожидание.

встречается:
в учебных примерах
в низкоуровневом коде
в некоторых оптимизационных или упаковочных сценариях

Fallthrough должен быть последней инструкцией внутри case

Такой код не сработает:

```go
switch x {
    case 1:
    if x > 0 {
    fallthrough
    }
    fmt.Println("done")
}
```

fallthrough оправдан, когда нужно намеренно выполнить общий блок следующего case, и это действительно делает код проще.
в большинстве бизнесовых задач сначала попробовать обойтись без него.

Часто более читаемо либо:
- вынести общий код в функцию. не делать огромный switch там, где пора выносить логику. switch на 100 строк с кучей сложной логики внутри каждого case - декомпозировать.
- объединить значения через запятую в одном case
- перестроить условия


### type switch

```go
func whatAmI(i interface{}) {
    switch v := i.(type) {
        case bool:
            fmt.Println("I'm a bool", v)
        case int:
            fmt.Println("I'm an int", v) // переменная типа int
        case string:
            fmt.Println("I'm a string", v) // тип string
        default:
            fmt.Printf("Don't know type %T\n", v)
    }
}
```

switch сравнивает значения. Type switch сравнивает какого типа значение лежит внутри interface, работает с интерфейсными значениями.

interface в Go может хранить значение разных конкретных типов. иногда программе понять, что ей передали: int, string, bool, что-то ещё.

i — интерфейсное значение
.(type) — специальная форма, допустима только внутри type switch
v := ... — переменная, внутри каждой ветки получит уже конкретный тип

удобно, внутри ветки можно работать с v уже как с нормальным конкретным типом.

В interface лежит строка, проверят какого типа значение внутри interface.

```go
var v interface{} = "hello" // interface{} -> string

func describe(i interface{}) {
    switch v := i.(type) {
        case int:
            fmt.Println("Число:", v*2)
        case string:
            fmt.Println("Строка длиной:", len(v))
        default:
            fmt.Printf("Неизвестный тип: %T\n", v)
    }
}

func main() {
    describe(21) // ветка case int
    describe("golang") // case string
    describe(true) // default, ветки case bool нет
}


// switch смотрит на значение:
switch x {
    case 1:
    case 2:
}

// Type switch смотрит на тип:
switch x.(type) {
    case int:
    case string:
}
```

type switch - форма switch, которая позволяет определить конкретный тип значения внутри интерфейса.
fallthrough в type switch не работает.

Встречается в:
- логике работы с interface{}
- универсальных функциях
- обработке данных разного формата
- отладке
- инфраструктурном коде
- старом коде, где интерфейсов много
- парсерах, обработчикх событий, API

Упражнение 5. fallthrough
при значении 2 выполнится и ветка 2, и следующая ветка.

```go
package main
import "fmt"
func main() {
x := 2
switch x {
case 1:
fmt.Println("one")
case 2:
fmt.Println("two")
// добавьте fallthrough
case 3:
fmt.Println("three")
}
}
```

Что должно получиться:
two
three

fallthrough не проверяет следующий case. Он просто заставляет выполнить следующий блок.

Упражнение 6. type switch
Что тренируем: различие между значением и типом.
Задача: Сделайте функцию, которая принимает interface{} и:
для int печатает число, умноженное на 2;
для string печатает длину строки;
для bool печатает булево значение;
для остальных типов печатает неизвестный тип.

```go
package main
import "fmt"
func describe(v interface{}) {
switch val := v.(type) {
case int:
// ваш код
case string:
// ваш код
case bool:
// ваш код
default:
// ваш код
}
}
func main() {
describe(21)
describe("go")
describe(true)
describe(3.14)
}
```

21 -> 42
"go" -> 2
true -> булево значение
3.14 -> неизвестный тип

switch сравнивает значения, а type switch сравнивает типы.
