Слайс - главная структура данных Go

Слайс - структура поверх массива:
- len - длина видимой части
- cap - ёмкость, сколько элементов можно добавить (длина базового массива)
- реальный массив скрыт внутри

```go
s := []int{1, 2, 3}
s = append(s, 4)
```

Slice (= Срез) - тип данных, последовательность динамической длины. Аналоги из других ЯП: динамический массив (при создании не указывается количество элементов); список.

Удобны, расширяемы, не обязательно знать зарание кол-во элементов.

Слайс - струкатура из 3-х элемнтов:
1) pointer: *array - ссылка на первый элемент слайса в базовом массиве (слайс не обязательно использует массив целиком). элементы хранятся в базовом массиве, слайс имеет только ссылку на него.
2) length: int - количество фактически используемых элементов в слайсе. С помощью параметра длины определяется последний элемент базового массива.
3) capacity: int - ёмкость. Количество элементов, которое влезает в базовый массив, с учётом не обязательного совпадения первого элемента слайса и первого элемента массива. Если используем массив из 10 элементов, начиная с 5-ого - cap = 5.

1 массив может использоваться несколькими слайсами.

#### Нулевое значение слайс

```go
var list []int // nil отсутствие значение

list = []int{} // значение есть, слайс без элемнтов {} - not nil
list == nil // false

len(list) == 0 // true
```

Проверка слайса на пустоту сравнением с nil не всегда сработает.
- Для проверки на пустоту - проверять len(list) == 0.

При работе со слайсами не должно волновать что это - нулевой слайс или слайс с нулевой длиной. Все функции работающие со слайсами, должны корректно работать и с нулевыми слайсами.

#### Можем аллоцировать памяить заранее, при создании слайса.

```go
list := make([]int, 5, 10)

list := make([]int, 0, len(nums)) // cap = размеру пред. слайса / переданного в функцию.

list := make([]int, len(nums)) // задать размер вместо ёмкости
```

Имеет смысл, чтобы избежать не эффективного множественнго создания новых базовых массивов и бесмысленного копирования элементов из старого в новый.

При cap = len(prevSlice) - размер результирующего слайса сразу правильный, не будет его пересоздания.

При len = len(prevSlice) - создастся слайс заполненный zero value. Обрабатывать придётся по другому, не как пустой слайс. Вместо append, присвоение по индексу.

- Если известен размер итогового слайса - по возможности, всегда аллоцировать память для него

#### Передача slice по значению и по ссылке

Передача слайса по значению
Неплохая идея. В самом слайсе не хранятся сами значения, а ссылка на первый элемент массива, тяжёлого копирования не будет.
Копируеются всего 3 параметра:
- ссылка на базовый массив
- размер
- ёмксоть

```go
list := []int{1, 2, 3, 4}

func handle(list []int) {
    list[1] = 123
}

handle(list)
fmt.Println(list) // [1, 123, 3, 4]
```

Передали слайс по значению, но данные всё равно изменились. Причиной тому, слайс хранит не значения базового массива, а ссылку на него. Независимо как передаём слайл - базовый массив всегда будет переда по ссылку.

```go
list := []int{1, 2, 3, 4}

func handle(list []int) {
    _ = append(list, 5)
}

handle(list)
fmt.Println(list) // [1, 2, 3, 4]
```

Ничего не поменялось. Смотрим исходный слайс, а не то что возвращяет функция append.

```go
list := []int{1, 2, 3, 4}

func handle(list []int) {
    // [1], 2, 3, 4
    // Передали в функции слайс длиной 1
    list = append(list, 5)
    // [1, 2], 3, 4 -> [1, 5], 3, 4
    // После append длина слайса увеличилась на 1. Окно просмотра базового массива также расширилось на 1
}

// Передаём слайс из 1 элемента
handle(list[:1])
fmt.Println(list) // [1 5 3 4]
```

Можно брать слайс от слайса. У них обоих общий базовый массив, но у них могут отличаться ёмкость, длина, ссылка на то какой элемент из базового массива будет первым.

Длина и ёмкость внешнего слайса не изменились - остались = 4. Они в отличие от базового массива передаются по значению, а не ссылке. От их мзенения внутри функции, снаружи ничего не изменится.

Чтобы добавить в переданный слайс и при этом не изменять внешний: Создать новый слайс вунтри функции и скопировать туда переданный

```go
list := []int{1, 2, 3, 4}

func handle(list []int) {
    newList := make([]int, len(list))
    copy(newList, list) // целевой слайс и исходный
    newList = append(newList, 5) // [1, 5]
}

handle(list)
fmt.Println(list) // [1, 2, 3, 4]
```

Внешний слайс не изменился, а во внутренний добавился элемент.

- Если хотим изменить переданный слайс и при этом не затрагивать внешний - перед изменением создать копию слайса.

Иногда хотим изменить внешний слайс. Например отсортировать его, не тратя память на создание ещё одного - сортировка внутри слайса.

Отделять целенаправленно изменение переданного слайса от случайного.


При len, cap = 4 добавление нового элемента, append создала новый массив и скопировала значения. В list & list2 - лежат слайсы с разными базовыми массивами. Изменение одного не влияет на другой.

В общем случае не пытаться догадаться как поведёт себя append - пересоздаст базовый массив или нет?

Можно посмотреть как выглядит функция в исходном коде Го, отвечающая за увеличение размера базового массива.
growSlice() удваивает размер массива, но только когда размер меньше 1024, если больше то ёмкость не в х2 (cap + cap), а на четверь (cap + cap/4).

Не знаем как в новых версиях Го изменится поведение внутренних функций.
Если завязывается на конкретную реализацию внутренних функций, конкретной версии языка - всё сломается, если в новой версии её изменят или захотим использовать комплиятор другой реализации.

```go

list[0] = 5

fmt.Println(list)  // [5, 0, 0, 0, 1]
```

- Результат работы append присваивать не новой переменной, а той же самой. Поведение будет ожидаемым.

Пишем функцию, которая считает целиком файл и ищет в нём последовательность байтов.

```go
// Чтобы найти в файле нужную последовательность байтов - регулярное выражение

var digitRegexp = regexp.MustCompile("[0-9]+") // только цифры

func FindDigits(filename string)[]byte {
    b, _ = os.ReadFile(filename) // считываем файл. игнорируем ошибку - в примере на важна

    return digitRegexp.Find(b)
}
```

Файл может оказаться очень большим (несколько ГБ). Если нас интерисует лишь его небольшая часть?
В результате применения regexp можем получить слайс размером в 10 элементов. НО у него останется тот же базовый массив.
Ситуация, что на протяжении работы программы оперируем слайсом размеров в 10 элемнтов, но программа съедает несколько ГБ памяти.

Если считываем файл не один, а много раз - съедим всю память компьютера.

«утечки» памяти после [:10] от огромного среза

Чтобы избежать этой проблемы:
создать новый слайс и переложить туда элементы

```go
func FindDigits(filename string)[]byte {
    b, _ = os.ReadFile(filename)

    b = digitRegexp.Find(b)

    res := make([]byte, len(b)) // cap = len, если cap не указана
    copy(res,b)
    // с помощью append можно написать более красивый вариант этой функции

    return res
}
```

При выходе из функции тяжёлый слайс в переменной b будет отчищен сборщиком мусора, так как нигде не исопльзуется.

#### Собственная функция append

Здесь Работа только с int и добавление только одного элемента.

```go
func Append(list []int, el int) []int {
    var res []int
    resLen := len(list) + 1

    // Проверить влезит ли resSlice в cap предыдущего, хватит ли в его базовом массиве места для ещё одного элемента
    if resLen <= cap(list) {
        // Если запаса cap хватает. Расширяем исходный слайс на 1 и сохраняем в результирующую переменную
        res = list[:resLen]
    } else {
        // Если место в массиве закончилось. Вычислить ёмкость итогового слайса
        // resCap := 3*len(list) // Это код сломается, если размер list = 0
        resCap:=resLen
        if resCap < 3*len(list) {
            resCap = 3*len(list)
        }

        res = make([]int, resLen, resCap)
        copy(res,list)
    }

    res[len(list)] = el

    return res
}
```

Чтобы она принмала несколько значений: el ...int. Обработка поменяется, тепереь это не int, а []int

### make, append, copy

make - лучший вариант для предвыделения памяти.
append может пересоздать внутренний массив -> старый ссылки станут неактуальны.

В базовом массиве не всегда должны содержаться нулевые значения, добавление в слайс не добавляет новые элементы, а перезаписывает предыдущие.

```go
s := make([]int, 0, 5)
s = append(s, 10)

s[100] = 11 // panic. Не можем обратится к элементу которого нет в срезе.
```

### Срезы слайсов (a[start:end])

Срез - слайс внутри другого слайса.
Оба используют один и тоже underlying array.

```go
a := []int{1,2,3,4}
b = a[1:3] // 2,3
```
