### Мониторинг и Observability в проде (на примере дашборда Grafana)

#### Инфраструктура под капотом:
- 17 серверов
- 157 контейнеров
- 11 баз данных
- 28 сайтов, доменов и поддоменов
- 48 фоновых задач только в одном Векторе
- Состав сервисов: платформа менторства, новая платформа обучения, две админки, CRM для продаж, свой шлюз к нейросетям (ai-gateway, через него ходят все сервисы), Вектор (сайт, миниапп, бот), сервис разбора собеседований, песочница для запуска кода, вики, почта, свой GitLab.

#### Что отслеживается в Grafana:
- Каждые 30 секунд проверка доступности всех сайтов и срока действия SSL-сертификатов
- Потребление памяти и CPU каждым из 157 контейнеров и динамика во времени
- По каждой ручке API: количество вызовов (RPS) и время ответа (latency)
- Логи всех сервисов в одном месте с поиском (Explore)
- Контроль свежести бэкапов
- Прогноз, через сколько дней закончится место на диске
- Аннотации деплоев на графиках (вертикальные пунктирные линии), чтобы сразу видеть, после какого релиза начались проблемы

#### Разбор дашборда Grafana (Home -> Dashboards -> 0. Главное -> Пульт):
Настройки панели: переключатель Деплои (вкл), быстрые ссылки Серверы и Логи (Explore), период Last 24 hours, обновление Refresh 1m.

- Секция «Всё ли живо»:
  - Сайтов лежит: 0 (зелёный)
  - Серверов недоступно: 0 (зелёный)
  - Сервисов не отвечает Prometheus: 0 (зелёный)
  - Ближайший сертификат истекает через: 5 weeks (зелёный)
  - Доступность сайтов за 7 дней: 97.76% (красный)
  - Сообщений в очередях RabbitMQ: production = 0, stage = 2 (зелёный)

- Секция «Сайты»:
  - Сетка из 28 карточек (2 ряда по 14 штук) по всем сайтам, ботам и сервисам — все в статусе OK (зелёные).

- Секция «Ошибки»:
  - porta: доля 5xx за 15 мин — 0.00% (зелёный)
  - sales-crm: доля 5xx — 0 (зелёный)
  - echo: доля 5xx — 0 (зелёный)
  - ai-gateway: ошибки провайдеров за 1 ч — 0 (зелёный)
  - График «Ответы 5xx в минуту» (08:00 — 06:00): линия porta на нуле, по шкале времени нанесены вертикальные пунктирные линии деплоев.
  - График «Ошибки в логах (level=error) в минуту» (08:00 — 06:00): отображает всплеск ошибок около 14:00 (пик ~110 ошибок/мин по main-bot-production) и небольшие всплески около 20:00–22:00 на фоне вертикальных меток деплоев.

Зачем это нужно: на собеседованиях постоянно спрашивают про метрики, логи и observability — наличие реального продакшн-мониторинга сильно выделяет опыт на фоне обычных пет-проектов.
