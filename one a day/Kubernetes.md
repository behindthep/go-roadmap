Kubernetes: pod, node, deployment

все проще, если разложить по уровням. Есть узлы — это обычные серверы. Есть поды — минимальные единицы, в которых живут контейнеры. И есть deployment — он следит, чтобы нужное количество подов всегда работало

Kubernetes - система, управляет контейнерами.
Запускает сервесы, следит, чтобы они работали и перезапускает их при сбоях. Нет ручного управления серверами.

Отправитель -> Cluster
Kubernetes управляет запуском и жизнью приложений. Управляет приложением, а не отдельным контейнером.

Node - сервер внутри Kubernetes. На нём запускаются контейнеры и поды.
Узел предоставляет CPU, память и сеть. Если узел падает, Kubernetes запускает поды на других узлах.

Pod - минимальная единаца в Kubernetes.
Внутри запускается 1 или несколько контейнеров. Контейнеры в поде всегда работают вместе.
Поды недолговечны и могут пересоздаваться.

Node 1 [ [App Sidecar] [App Sidecar] ]
Node 2 [ [App Sidecar] [App Sidecar] ]
Node 3 [ Упал ]

Pod = группа контейнеров.

Deployment управляет подами. Говорит Kubernetes, сколько подов должно работать, следит за количеством подов. Если под падает, Deployment создаёт новый. Нужен для масштабирования и обновлений.

Kubernetes cluster [
                Deployment:
    Node 1 [ [App Sidecar] [App Sidecar] ]
    Node 2 [ [App Sidecar] [App Sidecar] ]
    Node 3 [ [App Sidecar] [App Sidecar] ]
]

Deployment задаёт желаемое состояние приложения. Управляет подами и следит, чтобы их всегда было нужное кол-во.
Поды запускаются на узлах и могут свободно перемещаться между ними.
Если что-то падет, Kubernetes сам восстанавливает систему.
Kubernetes поддерживает нужно состояние приложения.
