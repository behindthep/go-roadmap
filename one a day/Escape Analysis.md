Escape Analysis: куда на самом деле попадают твои переменные

Судьба каждой переменной в Go решается еще на этапе компиляции. Именно тогда компилятор выбирает, где ей жить: в быстром стеке или в тяжелой куче, за которой присматривает Garbage Collector

### ЧТО ТАКОЕ ESCAPE ANALYSIS
Когда ты создаёшь переменную, Go решает куда её положить: в stack или в heap.

#### STACK:
быстрый, память освобождается автоматически при выходе из функции

#### HEAP:
медленнее, за ним следит Garbage Collector

Escape analysis, это анализ на этапе компиляции. Компилятор смотрит на каждую переменную и решает: она живёт только внутри функции или "убегает" наружу? Если убегает, значит в heap. Если нет, в stack.
Чем больше переменных остаётся на stack, тем меньше работы у GC, тем быстрее код

#### Схема: Escape Analysis в Go
go build, этап компиляции -> Компилятор:
- не убегает -> STACK (быстро, автоочистка)
- убегает -> HEAP (медленнее, нужен GC)

---

### КОГДА ПЕРЕМЕННАЯ УБЕГАЕТ В HEAP
Компилятор отправляет переменную в heap если не может гарантировать, что она не нужна за пределами функции.

#### Типичные случаи escape:
- Замыкание захватывает переменную
- Значение слишком большое для stack
- Кладёшь указатель в слайс, map или канал
- Возвращаешь указатель на локальную переменную
- Передаёшь значение в интерфейс (interface{} / any)

Важно: escape analysis работает на этапе компиляции. Он не знает что произойдёт в runtime, поэтому принимает консервативные решения. Если есть сомнения, отправит в heap

```go
// Убегает: возвращаем указатель наружу
func newUser() *User {
    u := User{Name: "Niyaz"} // escapes to heap
    return &u
}
// Не убегает: переменная живёт только внутри
func process() {
    u := User{Name: "Niyaz"} // остаётся на stack
    fmt.Println(u.Name)      // ...но fmt.Println принимает any
}
```

---

### КАК ПРОВЕРИТЬ: GO BUILD -GCFLAGS='-M'
Не нужно гадать, компилятор сам покажет что убегает.
Команда:
```bash
go build -gcflags='-m' ./...
```
Флаг -m включает вывод решений escape analysis. Можно удвоить -m -m для подробного объяснения почему переменная убежала

#### Что ты увидишь в выводе:
1. escapes to heap — переменная уходит в heap
2. does not escape — остаётся на stack
3. moved to heap — компилятор переместил в heap
4. leaking param — параметр функции утекает через возвращаемое значение или замыкание

```bash
// go build -gcflags='-m' main.go

// ./main.go:5:2: moved to heap: u

// ./main.go:9:13: ... argument does not escape
```

### КАК УМЕНЬШИТЬ АЛЛОКАЦИИ
Не нужно бороться с каждым escape. Но в горячих путях (hot path) это имеет значение

#### Что помогает:
- Возвращай значение вместо указателя, если структура маленькая
- Передавай конкретные типы вместо interface{}
- Используй sync.Pool для частых аллокаций одинаковых объектов
- Переиспользуй слайсы и буферы вместо создания новых
- Избегай замыканий в циклах

```go
// Убегает: указатель
func newUser() *User {
    return &User{Name: "Niyaz"}
}
// Не убегает: значение
func newUser() User {
    return User{Name: "Niyaz"}
}
```
