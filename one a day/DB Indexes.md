Индексы — структуры данных, ускоряют поиск и сортировку в таблицах БД. Помгает БД быстро находить строки, не просматривая всю таблицу (оглавление в книге).
В большой таблице индекс сокращает млн. операций до тысяч.
Индекс = быстрее поиск, меньше нагрузка.

Как индекс ускоряет запрос:
- Без индекса БД делает FULL SCAN: проходит каждую строку таблицы.
Чем больше таблица, те медленнее работает запрос
- С индексом БД делает INDEX SCAN: сразу переходит к нужному диапазону по дереву поиска.
С индексом по email поиск проходит мгновенно.

```sql
SELECT * FROM users WHERE email = 'x@y.com';
```

### Типы индексов в PostgreSQL

Каждый индекс решает свои задачи - нет универсального для всего.

1. B-дерево (B-tree) (по умолчанию):
- Универсальный: =, <, >, BETWEEN
- Самый распространенный тип индекса.
- Поддерживает быстрый поиск, вставку и удаление данных.
- Подходит для большинства сценариев.

2. Хэш-индекс (Hash index):
- Только точное равенство
- Использует хэш-функции для быстрого поиска по точным значениям.
- Не подходит для диапазонных запросов (например, `BETWEEN`).
- Исползуется редко

3. GIN
- Для массивов, JSONB, full-text
- Идеален для "поиска по содержимому"

4. GiST
- Геоданные, поиск по расстоянию, сложные структуры.


1. Составной индекс (Composite index):
- Индекс по нескольким столбцам.
- Полезен для запросов, которые фильтруют или сортируют по нескольким полям.

1. Полнотекстовый индекс (Full-text index):
- Используется для поиска по текстовым данным (например, LIKE или полнотекстовый поиск).

1. Пространственный индекс (Spatial index):
- Используется для работы с геоданными (например, координаты).

#### Когда индекс помогает, а когда нет

Индекс - трейд-офф: скорость чтения или скорость записи.
Индекс ускоряет SELECT, но может замедлять операции INSERT/UPDATE/DELETE

Использовать когда:
- часто ищешь по колонке
- таблица большая
- запросы фильтруют много данных

Не еспользовать если:
- таблица маленькая
- колонка почти одинаковая (низкая селективность - например, "gender")
- много вставок - индекс нужно обновлять каждый раз

❗Минусы индексов:
- Занимают доп. место на диске.

#### EXPLAIN ANALYZE

До / После

```sql
EXPLAIN ANALYZE SELECT ...

-- Без индекса:
- FULL SCAN
- Время больше
- Много проверок

-- С индексом:
- INDEX SCAN
- Время резко падает
- Меньше строк проходит
```

Индекс может ускорить запрос в 10-100+ раз.

Составные индексы — создаются на несколько столбцов таблицы. для ускорения запросов, которые фильтруют или сортируют данные по нескольким столбцам.

1. Создание составного индекса:
   - Пример:
CREATE INDEX idx_name ON table_name (column1, column2);

1. Использование в запросах:
   - Составные индексы эффективны для запросов, которые используют префикс индекса.
   - Пример:
SELECT * FROM table_name WHERE column1 = 'value1' AND column2 = 'value2';

1. Порядок столбцов:
   - Порядок столбцов в индексе важен. Индекс не будет использоваться, если запрос не включает префиксные столбцы.
   - Пример:
SELECT * FROM table_name WHERE column2 = 'value2'; -- Индекс не используется


- Составные индексы могут занимать больше места на диске.
- Не все СУБД поддерживают использование составных индексов для сортировки.


- Составные индексы могут значительно ускорить выполнение сложных запросов.
- Важно правильно выбирать порядок столбцов в индексе для максимальной эффективности.
