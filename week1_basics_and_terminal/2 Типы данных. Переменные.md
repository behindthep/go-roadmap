### Типизация Go
Go статически и строго типизированный язык - максимальную скорость работы и безопасность.
#### Статическая vs Динамическая. Когда проверяются типы
##### Статическая (Go, Java, C++): на этапе компиляции (до запуска)
Тип данных связывается с переменной при объявлении, известен на этапе компиляции и не меняется. 
Операторы и совместимость типов проверяются во время компиляции.
Ошибки типов видны до запуска, код не соберётся. Предсказуемость.
Исключение: Бестиповые константы - пока тип не зафиксирован, могут временно подстраиваться под тип переменной при присвоении.
##### Динамическая (Python, JavaScript, PHP): 
Тип привязан не к переменной, а к значению в ней. Тип узнаётся в runtime, переменная хранящая строку, далее в коде может начать хранить число.
Ошибки типов обнаруживаются уже во время работы.

#### Строгая/Сильная vs Слабая. Насколько язык строг к неявным преобразованиям типов во время выполнения (runtime)
##### Строгая/Сильная (Go, Python):
Переменной закреплён тип данных и язык запрещает неявные (автоматические) приведения, которые могут привести к потере смысла (сложение строки и числа).
    - 5 != 5.0, int + float64 к ошибке компиляции (даже свой тип на основе сущ. - для Go разные сущности). 
    - Необходимость явного преобразования для разных типов: float64(myInt) + myFloat.
##### Слабая (JavaScript, PHP, C):
Язык пытается неявно (автоматически) приводит когда считает уместным. В JS "5" + 2 ="52", "5" - 2 = 3. Может быть не очевидное поведение.

#### Утиная типизация (Duck Typing)
- Популярна в динамических языках. «Если это выглядит как утка, плавает как утка и крякает как утка, то это утка».
- Программе неважно, какого класса объект, главное — чтобы у него был вызванный метод. 
В Go есть её строгий аналог — интерфейсы, которые проверяются еще при компиляции.

### Разница между var, := и const:
#### 1. Выделение памяти и адресация (RAM)
- var и := — физически выделяет память в RAM (на стеке или в куче). К ней можно применить оператор взятия адреса &myVar.
- const — не выделяет память в RAM и не имеет адреса. Сущ. только на этапе компиляции, компилятор подставляет значение в код (inline). &myConst к ошибке компиляции.
#### 2. Область видимости (Где можно объявить)
- var и const — Объявляется как внутри функций, так и глобально вне их на уровне пакета. Если имя с заглавной буквы, её можно экспортировать в другие пакеты.
- := — Доступна строго внутри функций. Идеальна для локальных счетчиков в циклах for или коротких проверок в if.
#### 3. Обязательность инициализации (Когда задавать значение)
- var — Если значение не указано, нужно обязательно написать тип (var x int). Переменная получит zero-value типа.
- := — Нельзя опустить значение или явно указать тип данных.
- const — Значение должно быть определено и известно еще на этапе компиляции. Тип можно указать явно, либо он автоматически будут выведен из значения.
#### 4. Допустимые типы данных
- var и := — поддерживает любые типы данных (базовые, слайсы, массивы, структуры, интерфейсы, функции...). := - просто сокращение для var.
- const — поддерживает только базовые типы. Создать константный слайс, массив или структуру в Go нельзя.
#### 5. Множественное объявление (В несколько переменных)
- var — поддерживает группировку в блоки var (...). В одну строку можно объявить несколько переменных (var a, b = 1, "ok"; name, age := "Alice", 30), но типы нужно опустить для автоматического вывода.
- := — не поддерживает группировку в ().
- const — поддерживает блоки const (...). Если внутри блока пропустить значение для следующей строки, Go автоматически скопирует выражение из предыдущей. Внутри автоинкремент iota.
#### 6. Специфика типизации (Вывод типов)
- var и := — если тип не указан явно, он фиксируется при первом присвоении (из списка дефолтных).
- const — могут быть «бестиповыми» (untyped) - уникальная фича констант: остаются «чистым значением» и автоматически подстраиваются под тип выражения (const Pi = 3.14 сработает и с float32, и с float64).

### byte
В 1 байте 8 бит. 1024b = 1kb...
byte, если нужно очень много записать, вместо string, string занимает больше места на 1 символ.

В Go много работы с byte:
- Чтение файла происходит в byte
- Ответ на запрос к сайту приходит в byte. По сети передаются byte
Получаем в byte, затем преобразуем в необходимый тип.

### Типы данных
Данные в памяти - набор битов.
Типы данных определяют, как хранящиеся значения в переменных интерпретируются и доступные операции.

Go имеет встроенные типы и позволяет определять свои. 

### Встроенные типы данных:
#### Целочисленные типы:
Два типа числовых данных, которые отличаются характером их размеров (статическим или динамическим).
Большинство системных архитектур сегодня 32 / 64 -битные.
- независимые от архитектуры типы (int32), размер данных в битах постоянный, независимо на какой машине выполняется / для какой архитектуры компилируете код.
- зависимым от архитектуры. int при компиляции для 32/64-битной архитектуры, размер 32/64 бита.

Диапазоны основаны на размере бита. Для двоичных данных 8 битов могут представлять 256 уникальных возможных значений.
Архитектурно-независимые целочисленные типы:
- int8:         от -128                       до 127                        занимает 1 байт  (8 бит).
- int16:        от -32768                     до 32767                      занимает 2 байта (16 бит)
- int32 / rune: от -2147483648                до 2147483647                 занимает 4 байта (32 бита)
- int64:        от –9 223 372 036 854 775 808 до 9 223 372 036 854 775 807  занимает 8 байт  (64 бита)
- uint8 / byte: от 0                          до 255                        занимает 1 байт
- uint16:       от 0                          до 65535                      занимает 2 байта
- uint32:       от 0                          до 4294967295                 занимает 4 байта
- uint64:       от 0                          до 18 446 744 073 709 551 615 занимает 8 байт

* rune может быть 1-4 байтами (диапазон определяемым int32). rune для представления символа Unicode, символы ASCII могут быть представлены только int32.
* byte и uint8 после компиляции программы идентичны, byte для представления символьных данных в числовой форме, uint8 в программе представлен числом. Прояснить, когда в элементах символьных строк программа использует байты в качестве общего вычислительного измерения (в отличие от маленьких целых чисел, не связанных с таким измерением данных).

Зависимые от архитектуры целочисленные типы:
- int:  целое число со знаком.   В зависимости о платформы занимает в памяти 4 байта (int32)  / 8 байт (int64).
- uint: целое число беззнаковое. В зависимости о платформы занимает в памяти 4 байта (uint32) / 8 байт (uint64).

uintptr — беззнаковый целочисленный тип, размер в байтах = размеру указателя на архитектуре процессора (32 бита/4 байта на 32-разрядных системах и 64 бита/8 байт на 64-разрядных системах). Не ссылка на объект в памяти. Число (адрес), может хранить битовое представление указателя.
На 64‑битной архитектуре uintptr хранит беззнаковое целое число размером ровно 64 бита (принимать значения от 0 до 2^64 − 1). На 32‑битной — соответственно 32 бита.
Его размер специально сделан таким, чтобы он в точности совпадал с размером машинного указателя на этой платформе — это нужно, чтобы без потерь упаковывать адреса памяти в число и потом восстанавливать из него указатель.

int и uint имеют наиболее эффективный размер для определенной платформы (32 или 64 бита). Это наиболее используемый тип для представления целых чисел в программе.
Различные компиляторы могут предоставлять различный размер для этих типов даже для одной и той же платформы.

Переменной не указан тип, но присвоено целочисленное значение, ее тип - int.

#### Числа с плавающей точкой (floating-point numbers):
- float32: от 1.4 *10^-45  (-3.4 *10^38)  до 3.4 *10^38  (для положительных). в памяти 4 байта IEEE-754 32-bit. Обеспечивает 6  десятичных цифр точности.
- float64: от 4.9 *10^-324 (-1.8 *10^308) до 1.8 *10^308 (для положительных). в памяти 8 байт  IEEE-754 64-bit. Обеспечивает 15 десятичных цифр точности.
IEEE-754 - технический стандарт для представления и обработки вещественных чисел (с плавающей точкой) в компьютерах.

Действительные числа (вещественные числа (R) — все числа, которые можно разместить на числовой прямой).
Числа с плавающей точкой для представления действительных чисел, которые не могут быть выражены как целые.
Множество действительных чисел состоит из объединения двух непересекающихся множеств:
рациональные (можно представить в виде дроби) и иррациональные (pi или sqrt(2) имеют бесконечную и непериодическую последовательность цифр после запятой) числа. Компьютерная память конечна, записать или сохранить иррациональное число в точности внутри типа float невозможно.

#### Комплексные числа:
1+2i
- complex64:  вещественная и мнимая части float32. 
- complex128: вещественная и мнимая части float64.

#### Логический тип bool:
Значения true и false всегда будут объявляться строчными буквами t и f, это их предварительно объявленные идентификаторы в Go.

#### Строки string:
Строке соответствует строковый литерал - последовательность символов.
Структура данных байтовый срез, доступный только для чтения. 
Байт в строке представляет часть символа в кодировке UTF-8, кодировкой переменной длины и может представлять любой символ Unicode.

Строки в Go неизменяемы, после создания строки ее содержимое нельзя изменить посимвольно. 
Присваивая переменной str новую строку можно, переменная — это ссылка; ты просто перенаправляешь её на другой объект в памяти.

Строка содержать управляющие последовательности с обратного слеша \:
- \n: переход на новую строку
- \r: возврат каретки
- \t: табуляция
- \": двойная кавычка внутри строк
- \\: обратный слеш

- `` - необработанный строковый литерал. Символы внутри обратных кавычек отображаться как записаны, за исключением символа обратной кавычки.
a := `Say "hello"
to Go!\n`
Say "hello"
to Go!\n`

- "" - интерпретируемый строковый литерал. Внутри кавычек любой символ, кроме новой строки и незакрытых двойных кавычек. Двойные кавычки внутри - обратный слэш в качестве escape-символа.
a := "Say \"hello\" to Go!"

#### Строки с символами UTF-8
UTF-8 – схема для кодирования символов переменной длины 1-4 байта. Для данных UTF-8 (спец символов 世) тип-псевдоним rune (int32), может состоять из 1-4 байтов.
Римские символы (A), могут быть представлены значением ASCII (65).

for и range для индексации строк, подсчета байтов в строке. range индексирует символы в строке, возвращая за раз один символ и индекс байта, в котором находится символ в строке.

```go
a := "Hello, 世界"
for i, c := range a {
    fmt.Printf("%d: %s\n", i, string(c))
}
fmt.Println("length of 'Hello, 世界': ", len(a))

// 0: H
// 1: e
// 2: l
// 3: l
// 4: o
// 5: ,
// 6:
// 7: 世  символу требуется 3 байта
// 10: 界
// length of 'Hello, 世界': 13  строка длиннее, чем количество символов
```

#### Значение по умолчанию
Если переменной не присвоено значение, она получает значение по умолчанию для ее типа:
- Для числовых типов:   число 0
- Для логического типа: false
- Для строк:            ""

#### Неявная типизация
При определении переменной опускать тип, если инициализируем значением. Компилятор на основе значения неявно выводит тип переменной (int, float64)
Не указываем у переменной тип, нужно присвоить начальное значение. Объявление без типа и начального значения ошибка.

Узнать тип переменной - спецификатор "%T" при выводе функцией: 
```go
fmt.Printf("age type: %T\n", age) // age type: int
```

#### Выбор размера
Выбор правильного размера больше зависит от производительности целевой архитектуры, чем от самих данных.
Если не знаешь последствия для производительности программы:
Для целочисленных данных зависимые типы int или uint, вместо int64 или uint64. Увеличивает скорость обработки для целевой архитектуры.
- int64 и компилируете код в 32-битной архитектуре, для обработки значений минимум вдвое больше времени, для перемещения данных по архитектуре доп. циклы ЦП.
- int программа подстроится под архитектуру и быстрее обрабатываться.
Заранее знаете, не будете превышать определенный диапазон размеров, архитектурно-независимые типы – увеличить скорость и уменьшить использование памяти.
Знаете, данные не превысят значение 100 и только положительны, uint8 программу более эффективной, потребует меньше памяти.

#### Переполнение и сворачивание данных
Сохранить значение, превышает размер типа, Go переполнить и свернуть число. 
Зависит, когда вычислено значение – во время компиляции или выполнения.

```go
var maxUint32 uint32 = 4294967295 // Max uint32 size
```

Прибавим во время выполнения 1 к переменной при ее назначении, до компиляции - свернется до 0:

```go
var maxUint32 uint32 = 4294967295 + 1
```

Если время компиляции компилятор определить, что значение велико для хранения в указанном типе, ошибку constant 4294967296 overflows uint32.
