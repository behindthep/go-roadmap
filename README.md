# niyaz-golang-roadmap

🛠 Пошаговое создание каркаса через Git Bash
Перейдите в вашу рабочую папку (используя ваш алиас home) и выполните следующие шаги:
Шаг 1. Создаем папку проекта и переходим в неё
Замените my-go-project на любое имя вашего будущего приложения:

```
mkdir my-go-project
cd my-go-project
```

Шаг 2. Инициализируем Go-модуль
Это единственная официальная команда, которая создает файл go.mod. Этот файл управляет зависимостями и пакетами вашего проекта:

```
go mod init github.com
```

Шаг 3. Создаем стандартную структуру папок одной командой
В Go-сообществе принято разделять код на приватный (internal) и точку входа (cmd). Создадим их:

```
mkdir -p cmd/app internal/config internal/handler internal/service internal/repository
```

то это за папки:
• cmd/app/ — здесь будет лежать только главный файл main.go. Он просто запускает приложение.
• internal/ — код внутри этой папки защищен компилятором Go. Его невозможно случайно импортировать в чужие внешние проекты.
	• config/ — инициализация конфигов и файла .env.
	• handler/ — слой доставки (API, HTTP-контроллеры, обработчики запросов).
	• service/ — ядро проекта (вся бизнес-логика вашего приложения).
	• repository/ — слой работы с базами данных или внешними хранилищами.

Шаг 4. Создаем минимальный рабочий /app/main.go
Давайте положим в точку входа простейший код, чтобы ваши закомментированные пайплайны и тесты в будущем не падали при включении.

```
package main

import "fmt"

func main() {
	fmt.Println("Hello, Go World!")
}
```

✨ Итоговый вид проекта
Если вы откроете созданную папку в VS Code, структура будет выглядеть аккуратно и по-взрослому:

```
my-go-project/
├── cmd/
│   └── app/
│       └── main.go       # Точка входа в приложение
├── internal/             # Приватный код бизнес-логики
│   ├── config/
│   ├── handler/
│   ├── repository/
│   └── service/
└── go.mod                # Главный файл конфигурации Go
```
