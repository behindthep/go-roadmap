# Go Roadmap

Установить компилятор.

| Command  | Description |
| ------------- | ------------- |
| go help <команда> | Справка | 
| Build |
| go build | Скомпилировать код и получить бинарник |
| go run | Скомпилировать и запустить код |
| go generate | Запустить кодогенерацию |
| go install | Скачать утилиту, скомпилировать и установить бинарник в $GOPATH/bin (можно установить дебаггер: go install github.com/go-delve/dlve/cmd/div@latest) |
| Dependencies |
| go get | Скачать зависимость |
| go mod init | Создать файл со списком зависимостей |
| go mod tidy | Актуализировать файл со списком зависимостей |
| go mod vendor | Завендорить зависимости (весь исходный код зависимостей скопировать в каталог vendor проекта |
| Testing & Profiling |
| go test | Запустить юнит-тесты (или бенчмарки) |
| go tool cover | Собрать отчёт о покрытии кода после юнит-тестов |
| go tool pprof | Профилировать программу |
| Utils |
| go fmt | Прогнать автоформатирование кода |
| go vet | Прогнать линтеры |
| go env | Вывести список переменных окружения, используемых Go |

$GOPATH (/home/behindthep/go) бинарники, зависимости и служебные файлы. 
├──bin # бинарники программ, устанавливаемых 'go install'
|    └──foo # исполняемый файл программы foo
├─src
|   └──github.com/user
|       ├──foo
|       |   └──main.go # исходный код программы foo
|       └──bar
|           └──bar.go # исходный код библиотеки bar
└──pkg # служебные файлы Go

```
go mod init github.com
mkdir -p cmd/app internal/config internal/handler internal/service internal/repository
```

- internal/ — код внутри защищен компилятором Go. Его невозможно случайно импортировать в чужие внешние проекты.
	- config/ — инициализация конфигов и файла .env.
	- handler/ — слой доставки (API, HTTP-контроллеры, обработчики запросов).
	- service/ — ядро проекта (бизнес-логика).
	- repository/ — слой работы с БД или внешними хранилищами.

### Чтение чужого кода - самый быстрый способ вырасти

---

Избегайте коммуникаций через общую, разделённую память. Наоборот, делитесь данными в памяти через сообщения.
Конкурентность и параллелизм — не одно и то же.
Каналы для взаимодействия, мьютексы для разобщения.
Чем сложнее интерфейс, тем НЕнадёжней абстракция.
Копирование лучше зависимостей.
Защищай системные вызовы в коде тегами сборки.
Защищай кросс-вызовы cgo к коду C тегами сборки.
Применяя пакет unsafe, не рассчитывай на какие-либо гарантии.
Интроспекция ясной не бывает.
Полируй архитектуру, внятно называй компоненты, документируй детали.
