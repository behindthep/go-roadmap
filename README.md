```
mkdir -p cmd/app internal/config internal/handler internal/service internal/repository
```

- internal/ — код внутри защищен компилятором Go. Его невозможно случайно импортировать в чужие внешние проекты.
	- config/ — инициализация конфигов и файла .env.
	- handler/ — слой доставки (API, HTTP-контроллеры, обработчики запросов).
	- service/ — ядро проекта (бизнес-логика).
	- repository/ — слой работы с БД или внешними хранилищами.

Изначально в Go кооперативная многозадачность: пока код в горутине сам не передаст управление (попытавшись выполнить блокирующую операцию), забрать управление у этой горутины невозможно. 
С версии 1.14 планировщик стал в том числе вытесняющим - самостоятельно распределяет процессорное время между горутинами.
Горутина — легковесный поток, занимает меньше памяти, чем поток ОС. Среда выполнения Go выполнять несколько горутин на одном потоке ОС и быстро переключаться с выполнения одной горутины на другую благодаря их малому размеру. Вытесняющий планировщик равномерно распределять процессорное время между горутинами. 
Каналы — потокам обмениваться данными, служат для синхронизации их работы. горутина записать данные в канал, а другая горутина прочитать их.


Данные в компьютерах хранятся в бинарных последовательностей нулей и единиц. двоичное представление универсальности: данные- переменные, инструкции выполняемых программ, можно представить в бинарном виде. проектировать устройства хранения, для которых не важна природа данных.
при написании кода не с последовательностями бит, а с другими представлениями данных — «символ», «строка» или «число» - типами.

приводится ли значение переменной автоматически к нужному типу на стадии исполнения, языки со слабой и сильной типизацией. Сильная или слабая типизация отношение языка к неявным преобразованиям типов в различных контекстах. Чем сильнее типизация, тем меньше в языке автоматических и неявных преобразований.

<img width="2800" height="962" alt="image" src="https://github.com/user-attachments/assets/fb8b7085-5120-4104-a617-c0ee55b598c9" />

в условных конструкциях if языка Perl условием не только булевы переменные и логические выражения, также строки и числовые переменные. пустая строка, строка "0" или целочисленный и вещественный нули интерпретированы как false, а непустая строка или числовое значение, отличное от нуля, — true. слабая типизация.
Явной и неявной типизацией - способность компилятора выводить переменную из контекста. Явно типизированные языки - тип новых переменных, функций и их аргументов задавать явно. В языках с неявной типизацией не всегда необходимо, тип может вывести компилятор.

Python — динамическая и сильная типизация. тип переменной связан с её значением и определяется на этапе выполнения программы. 
у переменной, значение представлено в виде последовательности символов в одинарных кавычках, тип — str, строка. Если следующей инструкцией присвоить ей целочисленное значение, тип поменяется на int:
a = 'yandex'
a = 5 

при динамической типизации не указывают явно тип переменной, когда её объявляют. в Python к строке применима конкатенация посредством операнда +. Полученная строка из склеенных строк-операндов в порядке их представления в выражении:
a = 'yandex'
b = 'practiсum'
dot = '.'
result = a + dot + b # "yandex.practiсum" 

прибавить к строке число и получить на выходе исходную строку с приклеенным к ней числом в начале или в конце (в зависимости от порядка операндов), интерпретатор ошибку:
a = 'NO'
b = 10
res = a + b # ошибка: can only concatenate str (not "int") to str 

операция конкатенации работает со строками. Если бы Python автоматически преобразовывал типы перед сложением, ошибки бы не было. типизация в Python характеризуется как сильная:
res = a + str(b)  
При сильной типизации преобразования значений переменных не происходят автоматически — производить в коде явным образом.

JavaScript — динамическая и слабая типизация. динамическая типизация, тип переменной определяется её значением и может меняться в процессе выполнения программы:
var a = 'yandex'
a = 5 

var a = "yandex"
var b = 5
var res = a + b 

неявным образом, преобразует тип переменной b в строку, прежде чем выполнить конкатенацию. слабой типизацией.

C — статическая и слабая, явная типизация. типизация статическая. Тип переменной определяется на этапе компиляции, а не на этапе выполнения программы. При статической типизации конструкция объявления переменной содержит явное указание типа:
int a;
a = 42; 

автоматически преобразует типы переменных в выражениях, избавляя от необходимости делать это явно:
int a = 2;
char b = 'b';
int c = a + b; // 100, 'b' в ASCII представлен числом 98 

Go — статическая и сильная, неявная типизация. тип переменной определяется на этапе компиляции и синтаксически может быть опущен при её объявлении, если сразу инициализировать переменную значением. 
В Go сильная типизация: все преобразования нужно производить явным образом. Использовать значения разных типов в выражениях запрещено.

swap значений переменных без аллокаций (процесс выделения оперативной памяти для переменных и структур данных во время работы программы) в одну строку:
var a, b int
a, b = 5, 10 // a == 5, b == 10
a, b = b, a // swap: a == 10, b == 5 

конструкции для неявной типизации, при объявлении переменных тип опускается. тип переменной или константы определяется инициализирующим значением. не делает Go языком с динамической типизацией, тип переменной, объявленной, устанавливается на этапе компиляции.

var intVar = 10 // переменной intVar компилятор присвоит тип int 


Язык Go следует минималистичному подходу к системе типов, поэтому базовых типов не так много. В этом уроке рассмотрим примитивные типы — кирпичики, из которых складываются более сложные структуры данных. Композитным и ссылочным типам посвящена отдельная тема.

Целые числа
Для представления целочисленных переменных в Go есть ряд типов, различающихся лишь размерностью и отсутствием или наличием знака в них:
знаковые: int, int8, int16, int32, int64;
беззнаковые: uint, uint8, uint16, uint32, uint64.
Если размерности int64 недостаточно, можно воспользоваться типом big.Int из пакета math/big.
