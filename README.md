### week5

Недели 5–6: конкурентность в Go, горутины и каналы
Конкурентность — одна из главных причин, почему Go так любят в backend. Горутины позволяют запускать параллельные задачи легко и дёшево, а каналы дают понятный способ обмена данными между ними.

Но лёгкий старт здесь опасен. Написать go func() просто. Понять, когда горутина завершится, кто закроет канал, где может возникнуть гонка данных и почему программа зависла, уже сложнее.

На этом этапе нужно разобрать:

горутины
каналы
буферизированные и небуферизированные каналы
select
sync.Mutex
sync.WaitGroup
race condition
deadlock
fan-in / fan-out
worker pool
Здесь Go начинает отличаться от большинства языков, которые новичок мог учить раньше. Код уже не просто выполняется сверху вниз. Несколько частей программы могут работать одновременно, и нужно понимать, как они взаимодействуют.

Простой пример. Нужно сделать 1000 HTTP-запросов. Последовательно это может занять несколько минут. Через ограниченный пул воркеров на горутинах — десятки секунд. Но если просто запустить 1000 горутин без контроля, можно создать новую проблему: нагрузить внешний сервис, упереться в лимиты, словить утечки или зависания.

Конкурентность в Go — это про контроль параллелизма, а не про запуск большего числа горутин.

Если ты хочешь выйти на middle, этот блок нельзя проходить поверхностно. На собеседованиях по Go конкурентность всплывает постоянно.

Спрашивают не только определения, а реальные ситуации: что будет при чтении из закрытого канала, кто должен закрывать канал, как остановить воркеры, как найти race condition.

### week7
Алгоритмы и структуры данных. Big О, поиски, строки, стеки, де;нья, BFS/DFS. подготовка к алгоритмическим собеседованиям.

Недели 7–8: алгоритмы и структуры данных без фанатизма
Многие backend-разработчики не любят алгоритмы. Кажется, что в реальной работе ты не будешь каждый день разворачивать бинарные деревья и писать сортировки с нуля.

Это правда.

Но алгоритмы всё равно нужны. Не как спортивная дисциплина, а как тренировка мышления. Они помогают быстрее понимать задачи, видеть ограничения и объяснять ход решения.

На этом этапе стоит пройти:

массивы
стеки
очереди
связные списки на базовом уровне
хеш-таблицы
поиск
сортировки
простые задачи на строки
базовый BFS / DFS
Цель не в том, чтобы стать олимпиадником, цель не теряться на собеседовании, когда просят решить простую задачу, и не писать код хаотично.

Факт
На собеседованиях часто валятся не на сложных алгоритмах, а на простых задачах, где нужно аккуратно обработать крайние случаи.

Хорошая практика — решать задачи не только на платформах, но и проговаривать решение. Middle-разработчик должен уметь объяснить, почему выбрал именно такой подход, какая сложность у решения и где могут быть проблемы.

Без этого разработчик пишет код вслепую. Он может сделать handler, который возвращает JSON, но не понимать, что происходит между браузером, балансировщиком, сервисом и базой данных.

💡 Часть backend-багов выглядит как проблема кода, но на деле связана с таймаутами, сетевыми ошибками, неправильными статусами или неверной обработкой повторных запросов.

Для Go-разработчика это особенно важно, потому что стандартная библиотека net/http позволяет писать web-сервисы без тяжёлых фреймворков. Но чтобы использовать её нормально, нужно понимать саму модель HTTP.

Неделя 12: PostgreSQL, SQL и работа с данными
Без базы данных backend почти не существует. Даже простой сервис быстро упирается в хранение пользователей, заказов, событий, настроек и логов.

На этой неделе нужно изучить:

PostgreSQL
базовый SQL
SELECT, INSERT, UPDATE, DELETE
JOIN
индексы
транзакции

работу через database/sql или pgx
Главная ошибка новичков — думать, что база данных нужна только для сохранения данных. На самом деле плохой SQL может убить производительность сервиса быстрее, чем плохой Go-код.

Например, один запрос без индекса на большой таблице может начать выполняться секунды. Потом таких запросов станет сотни, и сервис начнёт тормозить под нагрузкой.

как отправить запрос из Go, но и почему база отвечает медленно.

совмещать Go и SQL. Не отдельно язык, отдельно база, а именно связку backend-сервиса с реальным хранилищем.

### (Me) VS Code Shortcuts

#### 1. Навигация по коду
* **Ctrl + P** (Быстрое открытие): введите первые буквы имени файла. Профи не кликают по папкам, они находят файлы мгновенно.
* **Ctrl + G** (Переход к строке): Когда линтер или тесты выдают ошибку на строке 142, они нажимают `Ctrl + G`, вводят `142` и сразу оказываются там.
* **Ctrl + Shift + O** (Навигация по символам): прыгнуть к функции, методу или переменной внутри открытого файла. Если ввести `:` после вызова, VS Code сгруппирует их по категориям.
* **F12** и **Alt + F12**: `F12` переносит к месту, где была объявлена функция или переменная. `Alt + F12` (Peek Definition) показывает это объявление в маленьком всплывающем окошке, не уводя из текущего файла.

#### 2. Мультикурсоры и «умное» выделение
* **Ctrl + D** (Множественный выбор): Выделите слово и нажимайте `Ctrl + D`. VS Code найдет следующие такие же слова в файле и создаст там курсоры.
* **Alt + Клик мыши**: Ставит курсоры в любые произвольные места на экране.
* **Shift + Alt + Стрелки (вверх/вниз)**: Мгновенно дублирует текущую строку кода. Больше никакого `Ctrl + C` -> `Enter` -> `Ctrl + V`.
* **Alt + Стрелки (вверх/вниз)**: Перемещает всю строку (или выделенный блок) выше или ниже по коду.

#### 3. Интегрированный терминал и Git
* **Ctrl + \`** (обратный апостроф): Открывает и скрывает встроенный терминал. Все команды, тесты и сборщики запускаются прямо внутри редактора.
* **Встроенный Git**: Вместо `git status` вкладку *Source Control* (**Ctrl + Shift + G**), где визуально проверяют изменения (диффы), пишут коммиты и пушат код одной комбинацией клавиш.

#### 4. Сниппеты и AI-ассистенты
* **Emmet**: `<div><p class="text"></p></div>`. `div>p.text` и `Tab`.
* **Пользовательские сниппеты** (Snippets): Они создают свои шаблоны. введя `rfce` + `Tab`, получают готовый каркас React-компонента.
* **AI** (Cursor): нейросетей для генерации шаблонного кода, написания тестов и быстрого поиска багов в редакторе.

#### 5. Zen Mode
* Нажатием **Ctrl + K**, затем **Z** они включают *Zen Mode*.
* Режим одного активного окна, где нет вкладок (файл открывается через `Ctrl + P`, а переключаться между последними открытыми файлами `Ctrl + Tab`).

#### 6. Независимость от мыши
* **Ctrl + \\** (Разделение редактора): Мгновенно дублирует вкладку и делит экран пополам (split screen). Профи всегда держат перед глазами файл с кодом слева и файл с тестами (`_test.go`) справа.
* **Ctrl + 1, Ctrl + 2, Ctrl + 3**: Переключение между разделенными окнами кода без использования мыши.
* **Ctrl + B** (Скрыть/показать боковую панель): Нажатием `Ctrl + B` вы убираете дерево папок слева, отдавая 100% экрана под код. В сочетании с быстрых поиском файлов через `Ctrl + P` боковая панель вообще становится не нужна.

#### 7. Golang
Официальный плагин Go от Google дает глубокую интеграцию, и вот как профи выжимают из нее максимум:

##### 7.1. Генерация шаблонного кода (Бойлерплейта)
* **Ctrl + Shift + P** -> `Go: Add Tags to Struct Fields`: Профи не пишут `json:"id"` вручную для каждого поля структуры. Выделяете структуру, вызываете эту команду, и VS Code сам генерирует теги (по умолчанию snake_case).
* Просто напишите букву(ы).

##### 7.2. Тесты
* **Ctrl + Shift + P** -> `Go: Toggle Test File`: Мгновенное переключение между файлом кода (например, `main.go`) и файлом его тестов (`main_test.go`). Не нужно искать его в дереве файлов.
* **Интерактивные кнопки над функциями**: Обратите внимание на мелкий блеклый текст `run test | debug test` прямо над вашими тестовыми функциями `func Test...`. Клик по ним запускает изолированный тест прямо в консоли VS Code, избавляя от необходимости писать громоздкие команды `go test -v -run ...` в терминале.
* **Ctrl + Shift + P** -> `Go: Generate Unit Tests for Function`: Поставьте курсор на сигнатуру сложной функции, вызовите эту команду, и VS Code сам сгенерирует для нее табличный тест (Table-driven test) со всеми заготовками под входные и выходные данные.

##### 7.3. Быстрая диагностика и интерфейсы
* **Shift + F12** (Найти все ссылки): Показывает лаконичный список всех мест во всем проекте, где вызывается эта функция или используется эта структура.
* **Ctrl + Shift + P** -> `Go: Implement Methods`: Если вам нужно, чтобы структура реализовала определенный интерфейс, эта команда сгенерирует заглушки для всех необходимых методов интерфейса автоматически.
