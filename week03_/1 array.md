Массив - фиксированный набор элементов. Используется редко. Понять, что он лежит в основе слайсов.

```go
var a [3]int = [3]int{1, 2, 3}
a[0] // 1
```

Неудобно - почти везде используются слайсы.

### Структуры данных

Любая базовая вещь в программировании, используется нами постоянно, даже если мы об этом не задумываемся.

Программирование 3 словами:
Алгоритмы над данными.

Алгоритмы - описание логики.
Данные - реальные частицы инфы, хранящиеся в памяти компьютера.

При работе с данными 3 основные операции:
- чтение
- запись
- удаление

Несовершенство компьютера не позволяет выполнить эти операции мгновенно. Время будет затрачено, но его количество зависит от того как данные распологаем в памяти - в какой структуре.

Большенство ЯП, обеспечивают необходимыми реализациями структур данных:
- массив
- стек и очередь
- связанный список
- хэш-таблица
- деревья
- графы

Одни из них строятся на других - заствляет изучать последовательно, одну за другой.

Понимание + и - в работе массива - даст понимание, зачем изучать что-то ещё помимо него.

Массив - СД, непреревную область в оперативной памяти, определённого размера, в которой каждый элемент занимает одинаково количество места, распологаясь ровно друг за другом.

В переменной распологается адрес на начало массива (его первый элемент).

В зависимости от ЯП, появляются возможность инициализировать как:

- статический массив:
язык с ручным управлением памятью

инициализируется на стеке. после завершения функции, в момент удаления кадра стека, он будет автоматически удалён.

неизменяемый размер

- динамический массив:

распологается в куче.

в ходе жизни может изменять свой размер.

если в языке нет сборщика мусора, удалять его придётся вручную, чтобы избежать утечки памяти. В противном случае он удалится автоматически, как только все ссылки на этот массив исчезнут.


Подобное расположение в памяти играет в две стороны:
+ компактность: процессор его хорошо кэширует, это повышает скорость выполнения кода
+ все элементы занимают одинаковое кол-во места: возможность получить адрес любого элемента массива за одинаковое кол-во времени (index * element size).
Сложность поиска в массиве = O(1), вне зависимости какой по счёту это элемент.

- Проблема вставки - нехватка места. Массив не возмоно расширить, добавить элемент в начало или в конец. Это обращение за пределы выделенной массиву области. Соседняя область памяти может быть занята данными других программ, к которым не можем получить доступ в целях безопасности.

Чтобы новый элемент появился в массив - сделать много не очевидных шагов, чтобы обойти все эти ограничения:
* выделить в памяти новый непрерывный участок, размером вмещяющий все элементы массива, с учётом нового
* скопировать туда все старые элементы и добавить новый.

Каждое добавление элемента в массив ведёт к его полному пересозданию в памяти - медленная операция.
Сложность вставки в массив = O(N)

Вставка в середину незаполненного массива тоже влечёт к прохождению части его элементов в цикле, сдвигая каждый его элемент вправо, освобождая нужную ячейку.


Удаление элемента из массива по логике должно работать быстро.
Удалением можно считать присвоение ячейка значения null.
Проблемы:
- сами типы не поддерживают это значение (массив int - допускает в качестве значений только цифры).
- null лишь очищает само значение, но не освобождает память, оставляя размер массива таким же.

Невозможность удаления элемента массива, заставляет пересоздавать массив в памяти, с уменьшеным на 1 размером. Проходясь по циклу скопировать каждый элемент массива, кроме удаляемого.
Сложность удаления из массив = O(N)


Исключением из этих правил - массив типа, допускающего значение null.

(не факт что в го также:)
Массив строк в памяти - массив адресов на начало своих строк, которые разбросаны где-то в памяти.

```go
0x20 0x21 0x22 0x23 0x24 0x25 0x26 0x27
0x00 0x00 0x00 0x52 0x00 0x00 0x00 0x94
адрес строки home   адрес строки car

0x52 0x53 0x54 0x55   0x94 0x95 0x96
h    o    m    e      c    a    r
```

Удаляя ненужный элемент из массива, в место адреса указываем null - это обрезает ссылку на строку. Она в последствии будет удалена автоматически с помощью сборщика мусора.
Учитывать, что сам размер массива остаётся незименным.

Массив хорош для чтения, но вставка и удаление при работе с большими данными, особенное когда эти две операции приходится выполнять часто - заставляет придумывать другие структуры хранения данных, которые лишены этих недостатков.

#### Связанный список

Набор узлов. Пред. узел имеет ссылку на след. узел, если список однонаправленный. Узел -> Next
Каждый узел имеет ссылки на след. и пред. узел, если список двунаправленный. Prev <- Узел -> Next

Узел - объект, хранящий сами данные и свойство ссылки(ок) ведущей на след. (и пред.) узел(ы).

Для взаимодействия с Linked List, есть указатели на начало (Head) и в некоторых случаях на конец (Tail) списка.

В отличии от массива, размер которого ограниченный ЯП, размер LL, ограничивается лишь размером оперативной памяти.
Отсутствие подобной компактности, не позволяет процессору также эффективно кэшировать эту СД.

-

Размер классического массива ограничен требованием непрерывного участка памяти и типом данных для индексации в языке программирования. В то же время связный список (Linked List) разбрасывает элементы по разным свободным адресам памяти и связывает их указателями.

Почему размер массива ограничен ЯП

• Непрерывность в памяти. Массив должен лежать в оперативной памяти одним цельным куском. Даже если свободной памяти много, операционная система не сможет выделить массив, если эта память фрагментирована на мелкие кусочки.
• Тип данных индекса. Язык программирования выделяет под размер и индексы массива конкретный целочисленный тип (например, 32-битный int в Java или C#). Из-за этого массив физически не может содержать больше \(2^{31}-1\) (около 2,14 миллиарда) элементов, сколько бы гигабайт ОЗУ ни стояло в компьютере.
• Статическое выделение (в некоторых ЯП). В языках вроде C или C++ размер статического массива фиксируется на этапе компиляции и помещается в стек, размер которого строго ограничен самой системой (обычно всего несколькими мегабайтами).

Почему связный список (LL) ограничен только ОЗУ

• Отсутствие привязки к сплошному блоку. Каждый узел списка выделяется в куче (Heap) отдельно и может находиться в любой свободной ячейке памяти. Узлы просто хранят ссылки на следующий элемент, поэтому фрагментация памяти им не мешает.
• Нет жесткого счетчика индексов. В классическом связном списке нет встроенного целочисленного индекса, который уперся бы в лимит типа int. Вы можете создавать новые объекты в куче до тех пор, пока в оперативной памяти не закончится свободное место.

-

Плюс сами ссылки для всех этих связей в памяти занимают доп. место.

Однако такая структура позволяет вставке работать быстрее.
Любая вставка, в начало, середину или конец, подразумевает лишь смену ссылок у соседних узлов.

Добавление в начало: ссылка next у нового узла указывать на пред. Head, а сам указетль Head указывать на новый первый элемент.
Если список изначально был пуст (Head = null), новый добавляемый в начало узел становится и головой и хвостом списка.

Добавление в конец: свойство next меняется у текущего хвоста. Затем сам хвост меняется на новй последний элемент.
Если список был пуст, новый добавляемый элемент становится и головой и хвостом списка.

Также вставка работает и с двунаправленным список, только помнить о ссылку prev ведущей на пред. узел.
Добавление в начало: если LL не был пуст - у текущей Head поменять ссылку prev на новый добавляемый узел.
Добавление в конец: устанавливаем ссылку prev для нового узла на текущий хвост.

Добавление новых элементов быстрее, по сравнению с массивом. Сложность = O(1).


LL удалось закрыть проблему вставок, не означает что в остальном также хорош:
Чтение, удаление данных, вставка в середину списка подразумевает постоянный поиск нужного узла.

Если в массиве поиск одинаково быстр для любого элемента.
В LL нет быстрого способа получения адреса - поиск сваливается в цикл, проверяя данные каждого узла. Сложность алгоритма = O(N).

Начиная с головы, через свойство next находим узел, после которого должна быть вставка. Затем изменяем 2 свойства next у нового и найденного узлов.

В двунаправленном LL, ещё прокидываем связи на предшествующие узлы.

Удаление в однонаправленном LL работает быстро только для первого элемента - не нужно искать, просто меняем указатель Head на след. узел.
Удаление остальных узлов аналогично пред. примерам:
Находим узел который надо удалить и меняем ссылки, будто этого узла никогда и небыло. В однонаправленном это 1 ссылка next у пред. узла.
Но что получить доступ к пред. узлу - надо найти его в цикле, вместе с удаляемым узлом - доп. переменная prev, на каждой итерации цикла, отстаёт на 1 узел от искомого узла.
Когда удаляемый узел найден, в переменной prev ссылка на предшествующий ему элемент.

В двунаправленном подобного не требуется - сам узел хранит ссылки на next и prev, который также нужно поменять.
Благодаря обратным ссылкам быстрое удаление в двунаправленном LL работает быстро для первого и последнего элемента, конечно при условии что есть указатели как на начало так и на конец списка.

СД не были придуманы случайно, каждая имеет особенности. Использование каждой из них целиком зависит от решаемой задачи.
