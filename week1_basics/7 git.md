
Воспринимать проекты на github как мою историю прогресса.

git - программа для контроля версий файлов.

Склонированный git clone репозиторий, локальная копия удалённого проекта сразу находится под управлением git на моём ПК.

git наблюдает за всеми файлами проекта и запоминает все изменения.
Можно быстро увидеть как код выглядел в определённоую дату раньше, перейти на эту версию файлов.

git commit - в этот момент git запоминает текущее состояние файлов проекта, какие файлы измены, как, кем, когда.
commit - версия файлов проекта. Каждый commit получает уникальный hash.

Переход к любой версии проекта осуществляется по hash commit.

git add - сказать git какие именно файлы закомитить; добавляет все (через точку . - все файлы начиная с текущей dir) или часть файлов, в которых были изменения в index, пометка для git, что они готовы к commit.
Файлы готовые к отправке в репозиторий нужно сначала поместить в специальное отделение - index (stage). Только файлы в index попадут в следующий commit.


Чтобы при работе множества людей с одними и теми же файлами не было хаоса - branch.

branch - последовательность коммитов, начиная от конкретного в прошлом.

Без branch commit разных людей смешивались и возникала бы путаница.

git branch - создать отдельную, личную branch. Это позволяет нескольким разработчикам работать параллельно, не мешаяя друг-другу.

Когда работа в branch закончена, их объединяют в одну общую.

Каждая отдельная задача делается в отдельной branch и лишь потом попадает в общую последовательность (с изменениями всей команды) main.

Новая branch основывается на main, отделяется и продолжает его.

git checkout - чтобы переключится на любую ветку и начать делать commits в неё.


Все commits и branches делаются и сущ. только локально на ПК. Проект общий, хранится на github в общем удалённом (remote) (на сервере github) репозитории. Из удалённого репозитория вся команда скачивает актуальные изменения.

git push - отправить локальные изменения в remote repository. Выполнять находясь в branch с моими commits.

```bash
git push origin branchname
```

origin - короткое название remote repository, псевдоним, чтобы не писать целый URL. Указывает на github project.

На github будет создана такая же ветка. Она появится в списке branches, её смогут скачать другие люди.

git pull - подтянуть, скачать с remote repository. Другой программист, может скачать мою branch с моими изменениями к себе на ПК, например чтобы продолжить в ней работу.

```bash
git pull origin branchname
```

Все commits из branch, находящиеся на серверах github передаются по интернету и окажутся на ПК члена команды. Теперь он тоже может перемещаться по ним, смореть историю, создавать собственные branch из моей.

Если появятся новые commits - снова git pull. Каждое утро все выполняют из основной branch main, получить всю работу сделанную командой за предыдущий день (период).

git rebase - чтобы изменения из моей branch попали в общую. Завершили работу и протестировали фичу, она готова для поподания в основную кодовую базу.

``` bash
# Находясь на своей рабочей branch, где готовая фича
git rebase main
```

Команда скопирует все commits моей branch и скопирует их в конец последовательности branch, указанной параметром (main).

Из главной branch собирается финальная версия приложения для передачи пользователям.

Если что-то пошло не поплану, закомитил баги. git хранит историю commits.

git revert hash (номер) - чтобы вернуться назад и исправить ошибку. Отменит все изменения сделанные в конкретном commit, в котором например находится bug.
Команда создаёт новый commit в branch, со всеми противоположными ошибочному commit изменениями.

Поэтому изменения в commits должны быть атомарными, маленькими, без смешения в 1 нескольких не связанных задач, чтобы при отмене отменился самостоятельный кусок, а не разбросанная, безсвязнная куча, часть из которой отменять не надо.

Оригинальный (ошибочный) и новый (порождённый revert) commits остаются в истории, к ним можэно перемещаться.
git ничего не забывает.
